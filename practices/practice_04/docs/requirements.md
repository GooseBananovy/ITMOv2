# Контракт review-mini

Целевое состояние сервиса. Фичи A и B реализуют в нём отказные и ошибочные пути;
успешный путь уже работает.

## Подписки (унаследованное поведение)

`subscribe(name) -> {"subscribed": True}` из `app/subscribe.py`.
Пустое или пробельное имя даёт `ValueError`. Повтор не создаёт дубликат.
Это поведение менять нельзя: оно служит регрессионной поверхностью.

## Ревью диффа

`review_diff(diff, client=None) -> dict` из `app/review.py`.

`client` — объект с методом `complete(system, user) -> str`. По умолчанию
`OllamaClient`, который ходит на `localhost:11434`. Инъекция клиента нужна
тестам: сеть в тестах не используется.

### Успех

```
{"status": "ok", "review": "<текст ревью>"}
```

### Фича A — валидация входа

| Условие | Ответ |
|---|---|
| дифф пустой или только пробелы | `{"status": "rejected", "code": "empty_diff", "message": "<...>"}` |
| `len(diff.encode("utf-8")) > MAX_DIFF_BYTES` | `{"status": "rejected", "code": "diff_too_large", "message": "<...>"}` |

`MAX_DIFF_BYTES = 8192`.

Главное требование: **при отказе клиент модели не вызывается**. Проверяется
клиентом, который падает при вызове, а не подсчётом времени ответа.

### Фича B — ошибка зависимости

Ожидание модели ограничено `REVIEW_TIMEOUT_SECONDS = 30`.

| Условие | Ответ |
|---|---|
| ожидание вышло | `{"status": "error", "code": "model_timeout", "message": "<...>"}` |
| соединение не установлено | `{"status": "error", "code": "model_unavailable", "message": "<...>"}` |
| модель ответила HTTP-ошибкой | `{"status": "error", "code": "model_http_error", "message": "<...>"}` |
| ответ без ожидаемых полей | `{"status": "error", "code": "model_bad_response", "message": "<...>"}` |

`message` пишется для человека и называет причину. Наружу исключения не
пробрасываются. Отказы фичи A продолжают работать без изменений.

## Запрещено без отдельного поручения

- менять этот файл;
- ослаблять `scripts/check.sh`, чтобы получить зелёный результат;
- добавлять зависимости вне стандартной библиотеки;
- трогать `practices/practice_03/`.
