# Практика 4: среда, skill, MCP и hook на review-mini

Проект — `review-mini`, выращенный из `Notify Mini` практики 3: подписки
остались как регрессионная поверхность, сверху добавлено ревью диффа локальной
моделью Ollama. Зависимость одна и настоящая, её можно остановить и посмотреть,
что будет. Весь код на стандартной библиотеке, поэтому worktree для второй фичи
не потребовал ни установки, ни виртуального окружения.

Две фичи: **A** — валидация входа, отказ не доходит до модели; **B** — ошибка
зависимости превращается в ответ по контракту, а не в трейсбек.

Контракт: [`docs/requirements.md`](docs/requirements.md).
Проверка: `sh scripts/check.sh` из этого каталога.
Подтверждения прогонов: [`evidence/`](evidence/).

## Блок А. Настроенная среда

### Правила — `AGENTS.md`

[`AGENTS.md`](AGENTS.md) называет контракт, пример теста, **действующую** команду
проверки и список запретов. Ссылка на [`docs/style-guide.md`](docs/style-guide.md)
стоит внутри `AGENTS.md`, а не в поле `instructions` конфига: `instructions`
файлы не подгружает.

Работает: в прогоне на вопрос «работает?» агент сам пошёл выполнять
`sh scripts/check.sh` — команду он взял из правил, а не угадал.

### Skill — `review-acceptance`

[`.opencode/skills/review-acceptance/`](.opencode/skills/review-acceptance/):
процедура сдачи фичи плюс `references/writing-tests.md`. Внутри не только текст,
но и `scripts/acceptance.sh`, который проверяет запреты кодом.

Применение видно в логе прогона: первым действием агент вызвал skill и прочитал
reference — [`evidence/stage4-feature-a.txt`](evidence/stage4-feature-a.txt).

### MCP — два сервера

- **свой** `review-mini` (stdio, `fastmcp`) — инструмент `review_diff`, см. блок В;
- **внешний** `context7` (remote) — документация библиотек.

Context7 отвечал на вопрос, который реально был нужен фиче B: как задать таймаут
в `urllib.request.urlopen`. Два вызова, ответ со ссылкой на файл документации
cpython — [`evidence/mcp-context7.txt`](evidence/mcp-context7.txt).

### Hook — `check-after-edit`

[`.opencode/plugins/check-after-edit.js`](.opencode/plugins/check-after-edit.js)
регистрирует `ctx.tool.hook("execute.after", ...)` и после каждой правки
файла запускает тот же `scripts/check.sh`.

Срабатывание по событию подтверждено журналом, который плагин ведёт сам:
[`evidence/hook-runs.txt`](evidence/hook-runs.txt). Там видно и FAIL, и PASS,
в том числе FAIL в тот момент, когда агент нарочно сломал код для мутационной
проверки.

### Обоснование подключений

Каждое подключение закрывает конкретную дыру, а не добавлено для счёта.

| Что | Зачем именно здесь |
|---|---|
| `AGENTS.md` | в проекте один доверенный раннер, а чужой skill зовёт `npm test`. Без явного правила агент выполнит команду из skill |
| свой skill | процедура «покажи падение» не держится на доброй воле: `acceptance.sh` проверяет запреты кодом и возвращает ненулевой код |
| Context7 | фиче B нужен был точный способ задать таймаут в stdlib. Это вопрос к документации, а не к памяти модели |
| свой MCP | агент отдаёт свой дифф на ревью локальной модели, не читая код сервиса. Практика 3 становится инструментом практики 4 |
| hook | проверка не должна зависеть от того, вспомнил ли агент её запустить. Запускается по событию правки |

Чего **не** подключал: Playwright MCP (нет UI), GitHub MCP (не нужны права на
issues), LSP (в OpenCode 2 не работает, см. слайд 25), AST-индекс (проект в
несколько файлов).

## Блок Б. Skill: создание и разбор

**Свой** — `review-acceptance`, с автоматизацией. `scripts/acceptance.sh`
проверяет: защищённые файлы не менялись, новых зависимостей вне stdlib нет,
отладочных `print(` в `app/` нет, `practices/practice_03` не тронут, раннер
зелёный. Ненулевой код выхода блокирует сдачу.

Проверен не чтением, а прогоном на нарочно сломанном состоянии: ловит все четыре
нарушения — [`evidence/skill-acceptance-check.txt`](evidence/skill-acceptance-check.txt).

**Чужой** — `test-driven-development` из superpowers, вендорен с пиннингом на
коммит, прочитан целиком до подключения. Разбор своими словами и два найденных
конфликта с нашим проектом — в [`docs/skills.md`](docs/skills.md).

## Блок В. Собственный MCP

[`mcp/review_mcp.py`](mcp/review_mcp.py) на `fastmcp`, транспорт stdio, портов не
открывает. `fastmcp` подтягивается через `uv run --with`, в систему ничего не
ставится.

Инструмент `review_diff(diff)` — обёртка над сервисом: агент получает ревью
диффа от локальной модели, не читая код сервиса.

Подключение и вызов: [`evidence/mcp-review-mini.txt`](evidence/mcp-review-mini.txt).
Ошибочный вход: [`evidence/mcp-bad-input.txt`](evidence/mcp-bad-input.txt).

Запуск идёт через [`mcp/serve.sh`](mcp/serve.sh), который находит проект от
своего пути: `cwd` в конфиге резолвится от каталога workspace, и на этом я уже
один раз получил зависший старт сессии.

## Как проверить самому

```sh
cd practices/practice_04
sh scripts/check.sh                                          # тесты
sh .opencode/skills/review-acceptance/scripts/acceptance.sh   # запреты
opencode debug config                                        # источники конфигурации
```

Для MCP и агента нужны запущенная Ollama (`systemctl start ollama`), сборка
`itmo-local:latest` из практики 3 и переменная `VSELLM_API_KEY`.

## Ограничения, о которых честно

- `opencode api skill.list` отдаёт пустой список, хотя skills работают: это
  видно только по вызову в сессии, не по API;
- `opencode mcp list` не видит конфиг практики, статус подключения приходится
  искать в логах сервера (`--log-level debug`, строка `mcp connected`);
- таймаут **соединения** (а не чтения) приходит как `URLError` и попадает в код
  `model_unavailable`, а не `model_timeout`. Проверено на живой зависимости:
  таймаут чтения даёт `TimeoutError`, закрытый порт — `URLError`;
- hook возвращает вердикт агенту через переназначение `event.result`; мутация
  вложенного поля на месте до модели не доходит.
