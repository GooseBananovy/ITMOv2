## Когда применять

Любая правка кода в `app/` или `tests/`. Процедура кончается не словами «готово»,
а выводом двух команд.

## Процедура

1. Прочитай `docs/requirements.md` — там коды ответов и лимиты. Контракт менять
   нельзя.
2. Прочитай `references/writing-tests.md` перед первым тестом.
3. Напиши тест, который падает на текущем коде. **Покажи вывод падения**: без
   него считается, что тест ничего не проверяет.
4. Сделай минимальное изменение, которое делает тест зелёным. Ничего лишнего
   рядом не трогай.
5. Прогони доверенный раннер:

   ```
   sh scripts/check.sh
   ```

6. Прогони машинную проверку запретов:

   ```
   sh .opencode/skills/review-acceptance/scripts/acceptance.sh
   ```

7. Отчитайся: что изменил, какой тест это проверяет, какой был вывод падения и
   какой стал после. По каждому утверждению — `файл:строка`.

## Чего делать нельзя

- объявлять фичу готовой без вывода раннера;
- ослаблять `scripts/check.sh` или удалять мешающий тест;
- менять `docs/requirements.md`;
- добавлять зависимости вне стандартной библиотеки.

Если проверка краснеет и причина непонятна — остановись и спроси, а не правь
раннер.
