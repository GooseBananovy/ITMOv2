Проверка второй половины требования слайда 14: "его результат вернулся агенту".
3 октября 2026.

Проверял не предположением, а просьбой к агенту процитировать дословно весь
текст, который вернул ему инструмент записи файла.

=== ДО (плагин менял event.result.output на месте) ===

  Вопрос: "Создай файл инструментом write и процитируй дословно и полностью то,
  что вернул тебе инструмент."

  Ответ агента:
    Результат инструмента записи файла процитирован дословно и полностью
    (больше в ответе инструмента ничего не было - ни до, ни после этой строки,
    никаких служебных пометок):
      Created file successfully: tmp_hook_probe.txt

  То есть hook срабатывал (журнал hook-runs.txt это показывает), но его вердикт
  до модели не доходил.

=== ПРИЧИНА ===

  Документация V2: event.result можно ЗАМЕНИТЬ целиком
  (event.result = { ...event.result, metadata: ... }), а мутация вложенного поля
  на месте не учитывается. У результата есть content, output и metadata.

=== ПОСЛЕ (плагин собирает новый объект результата) ===

  Ответ агента, дословная цитата результата инструмента write:

    Created file successfully: tmp_hook_check.txt

    [check-after-edit] PASS - sh scripts/check.sh
    ----------------------------------------------------------------------
    Ran 10 tests in 0.001s

    OK
    Проверка проекта зелёная.

  И отдельно словами агента: "В выводе действительно были служебные пометки
  после подтверждения записи - автоматический прогон [check-after-edit] PASS
  с результатом тестов."

Вывод: "hook сработал" и "агент увидел результат" - два разных утверждения.
Первое доказывается журналом плагина, второе - только цитатой агента.

Побочное наблюдение про безопасность: в обоих прогонах агент отдельно сообщил,
что блок <system-update> с mcp_instructions от сервера context7 он не выполнял
как команду, потому что это не инструкция пользователя. Инструкции, приходящие
от MCP-сервера, - это данные, и агент это выдержал.
